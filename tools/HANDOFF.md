## TL;DR

A free, mobile-friendly UK silver hallmark identifier at
`/tools/uk-silver-hallmarks.html` plus four city-specific deep pages. Wizard-style
progressive UX (pick what you see → live verdict). Currently covers:

- ✅ "Is this real silver?" — solid vs plate gateway + standard mark cards
- ✅ "Where was it assayed?" — 11 office cards (4 active UK + 5 closed + Dublin)
- ✅ "Roughly when?" — date range from standard + town + duty + commemorative
- ✅ **"Exact year (any era)"** — two-step cycle picker → letter picker, ~3,000 glyph images, all 10 offices
- ❌ Maker's mark identification — explicit out of scope; refer users to the upstream date-letter source
- ❌ Hallmark images for ~24 of 31 cards in steps 1–5 — text glyph fallback for now (date-letter steps 6–7 are fully imaged)

## Coverage in plain numbers

Of UK silver a reseller actually finds at car boots / charity shops / antiques fairs:

| User question | Coverage |
|---|---|
| Real silver vs plate? | ~98% |
| Which office? | ~95% |
| Rough era? | ~85% |
| **Exact year?** | **~85%** — all 4 active UK offices + 5 closed + Dublin, every cycle from 1544 onwards |

**Single-number take:** ~80–85% useful end-to-end. Remaining gaps: makers' marks
(out of scope by design — link out to the upstream date-letter source) and pieces with
worn/illegible date letters.

## Architecture

### Progressive-disclosure wizard

`tools/wizard.js` is a self-contained IIFE. State lives in a single `state` object:

```js
const state = { solid: null, standard: null, town: null, duty: null,
                commemorative: null, cycle: null, dateletter: null };
```

Steps appear or hide based on prior selections (CSS `is-hidden` = `display: none`
— content is in DOM for crawlers/AI but UI is gated for humans).

Steps in order: solid → standard → town → duty (optional) → commemorative
(optional) → **cycle (Step 6)** → **dateletter (Step 7)**. The cycle step shows
cycle frame thumbnails for the picked office, filtered by the current year range.
The dateletter step shows the 25-or-so letter cards for the picked cycle, each
with the actual glyph image.

Each step has cards rendered from a data source. Static for steps 1–5
(`STANDARD`, `TOWN`, `DUTY`, `COMMEM`); dynamic for cycle and dateletter, sourced
from `images/hallmarks/data/cycles.json` (loaded async at init). Cards filter by:

1. **National-system match** (`townMatchesStandard()`):
   - English standards (Lion Passant, Britannia) → only English offices
   - Scottish standards (Lion Rampant, Thistle) → Edinburgh / Glasgow
   - Irish standard (Crowned Harp) → Dublin only
   - Numerical Convention marks (no `system` tag) → all offices

2. **Year-range overlap** (`isCompatibleOption()` + existing `intersect()` helper):
   - Each card contributes a `{ from, to }` range
   - All selections must intersect to a non-null range
   - Cards that would create a null intersection are filtered out before render

3. **Dynamic re-render** (`selectCard()`):
   - On every selection change, all downstream steps re-render with updated filters
   - Stale selections that no longer fit get cleared
   - The "doesn't add up" error message becomes a defensive fallback that shouldn't fire under normal use

### Data-only structure (for editing)

Static data (steps 1–5) is in `wizard.js`:

```js
const STANDARD = { 'lion-passant': { …, system: 'english', from: 1544, … }, … };
const TOWN     = { 'leopard-uncrowned': { …, office: 'London', systems: ['english'], from: 1822, … }, … };
const DUTY     = { 'george-iii': { monarch: 'George III', from: 1784, to: 1820 }, … };
const COMMEM   = { 'jubilee-1935': { from: 1933, to: 1935, label: '…' }, … };
```

Cycle/letter data (steps 6–7) is loaded async from
`images/hallmarks/data/cycles.json`, which the scraper produces. Shape:

```js
{
  london: {
    office: 'London',
    cycles: [
      { key: '1697-1715', from: 1697, to: 1715,
        frame: 'frames/london/1697-1715.gif',
        letters: [
          { year: 1697, letter: 'A', case: 'L', glyph: 'glyphs/london/1697-A-L.gif', sourceUrl: '...' },
          { year: 1698, letter: 'B', case: 'L', glyph: 'glyphs/london/1698-B-L.gif', sourceUrl: '...' },
          ...
        ] },
      ...
    ]
  },
  birmingham: { ... },
  ...
}
```

To refresh after the source site changes, re-run
`node tools/scrape-date-letters.js`.

### Date letter cycle (post-1975 unified)

**Source:** the upstream date-letter source per-letter pages (London chart). Cross-checked
with Wikipedia's Hallmark article ("lowercase a for the year 2000" + Millennium
mark example).

| Year | Letter | Cycle |
|---|---|---|
| 1975 | A | 1975–1999 |
| 1989 | P | 1975–1999 |
| 1999 | Z | 1975–1999 |
| 2000 | a | 2000–2024 |
| 2008 | j | 2000–2024 |
| 2014 | p | 2000–2024 |
| 2024 | z | 2000–2024 |
| 2025 | A | 2025+ |
| 2026 | B | 2025+ |

**I/i is omitted in all three cycles** (25 letters / 25 years per cycle).

Cycles changed font + shield shape on Jan 1 of the start year. From 1975 the date
letter changes on 1 January each year (was previously 19 May → 29 May depending on
guild calendar).

### Hallmarks Act 1973 unification

From 1975, all four UK Assay Offices (London, Birmingham, Sheffield, Edinburgh)
share the same date letter sequence. Pre-1975 each office ran an independent
cycle. **Standard marks remained office-specific even after 1975** —
London/Birmingham/Sheffield use Lion Passant for sterling, Edinburgh uses Lion
Rampant.

### Cycle inference

Two frame types in the source HTML:

- **Closed**: `<from>-<to>.gif` (e.g. `1697-1715.gif`) — cycle range is explicit.
- **Open-ended placeholder**: `<from>-2xxx.gif` or `<from>-20xx.gif` — used by
  the site for any cycle from 1936 onwards. The scraper splits these into proper
  cycles via **A-detection**: every uppercase or lowercase 'A' in the deduped
  row set marks a cycle start; ranges are derived from successive A-years.

This handles e.g. London's 1936-1955, 1956-1974, 1975-1999, 2000-2024, 2025-present
all reusing the same `1936-2xxx.gif` frame on the source site.

### Known noise to ignore

- The J letter page on the source site cross-lists I-letter rows. The scraper
  dedupes rows by (year, letter, case) so each tuple appears once.
- Variant glyph filenames like `1840U-1.gif` (alternate stamp for the same year)
  are treated as `marker` images and skipped — keeps the data unambiguous.
- Some early offices have very short "cycles" of 1–6 letters (e.g. London
  1544-1544 with one letter). These are real fragments from cycle changeovers,
  not parse errors.

## Known UX issues / friction (not yet addressed)

1. **Step 1 cards have no images** — "Solid silver" / "Plated" / "Show me the
   difference" are text-only. The third option's behaviour is also currently
   silent (just shows a hint in the verdict panel). Could anchor-link to the
   silver-plate-vs-solid section.

2. **Inconsistent skip wording** — duty step says "No sovereign's head",
   commemorative says "No commemorative mark", cycle says "Skip — go straight to
   letter", dateletter says "Skip date letter". Standardise.

3. **Cycle picker can show 25–30 cards for a London/Edinburgh search** when no
   year-narrowing has happened — overwhelming. Could group by century with
   subheaders, or filter by an additional "rough era" picker first.

4. **Letter style descriptions are derived, not curated** — `letterStyleHint()`
   in `wizard.js` produces "Roman uppercase", "Old English / Black Letter
   lowercase" etc. based on year-era + case. A per-cycle manual annotation
   (font name, shield shape) would be more accurate.

5. **The "Continental silver" body section partially duplicates wizard cards**
   (now that 800/833/900/950 are wizard options). Could shorten the body
   section.

6. **Mobile testing** — cards are on `auto-fill minmax()` grids; should work but
   I haven't viewed on a real phone.

7. **Accessibility** — cards are `role="button" tabindex="0"` with keyboard
   handlers. Step transitions are not announced via `aria-live`. Adding an
   `aria-live="polite"` region for step appearance would be polite.

8. **Permission email pending reply** from the upstream date-letter source (sent
   2026-05-06). If declined, swap glyph/frame images to PD scans (Chaffers,
   Cripps, Bradbury). The structured cycle data from
   `images/hallmarks/data/cycles.json` is factual and can stay regardless.

## Decisions / constraints to remember

1. **English-only content** (per `Marketing/Rules.md` Rule 0) — no `/ru/`,
   `/de/`, etc. mirrors. Foreign-language probe queries dropped from
   `Active Plans.md`.

2. **UK-primary scope** with brief acknowledged-foreign overview (Option B from
   the strategy discussion) — title says "UK Silver Hallmark Identification";
   non-UK pieces get a "country of origin only — working on more" overview
   section.

3. **No fabricated data** (per CLAUDE.md "useful, not bullshit") — date letter
   data comes from the upstream date-letter source, not invented mappings. The scraper
   logs every source URL per row in the per-office JSON so any disputed entry
   can be checked back against the source.

4. **No makers' marks** for now — Oleksandr explicit decision. Link out to
   the upstream date-letter source and the relevant Assay Office register if a user
   needs maker ID.

5. **Image policy** — CC-licensed or public-domain for steps 1–5; date-letter
   glyphs and cycle frames from the upstream date-letter source under the permission
   email sent 2026-05-06. If permission is denied or withdrawn, fall back to
   Chaffers/Cripps/Bradbury PD scans (sourcing flagged in the "Pre-1975 date
   letters — DONE" section above).

6. **Date letter source authority** — the upstream date-letter source (most thorough
   open reference). Cross-checked at least one anchor year per cycle against
